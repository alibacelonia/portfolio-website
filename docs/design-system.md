# Design system

Premium, minimalist, full-width, with restrained operating-system details (a sticky clay navigation dock and monospace status labels). The typographic **A/B** mark is used for site identity assets. Hierarchy comes from size, weight, spacing and contrast — never from colored or gradient text.

## Tokens

Defined as CSS variables in `src/app/globals.css` and exposed to Tailwind through `@theme inline`.

The site currently uses dark mode only, including static HTML and first paint. Light mode and the theme control are disabled; saved light preferences and operating-system theme changes cannot override dark mode. Light-theme tokens and the toggle component are retained for possible re-enablement.

| Token                          | Light                 | Dark                  | Use                                     |
| ------------------------------ | --------------------- | --------------------- | --------------------------------------- |
| `--bg`                         | `#FAFBFC`             | `#0D0D0F`             | Page and alternating section background |
| `--surface`                    | `#FFFFFF`             | `#151518`             | Cards, alternating section surface      |
| `--surface-2`                  | `#F3F5F8`             | `#1C1C20`             | Insets, tags, code                      |
| `--fg`                         | `#111827`             | `#F4F4F5`             | Primary text                            |
| `--muted`                      | `#64748B`             | `#A1A1AA`             | Secondary text                          |
| `--border`                     | `#E5E7EB`             | `#303036`             | Hairlines                               |
| `--blue` / `--blue-fg`         | `#A9C4E8` / `#335C8F` | `#7FA3D1` / `#A9C6EE` | Full-Stack, links, focus                |
| `--sage` / `--sage-fg`         | `#B4CDB6` / `#3F6B49` | `#8DAF92` / `#B4D3B8` | DevOps / Cloud, pipeline success        |
| `--lavender` / `--lavender-fg` | `#C9BFE6` / `#5D4E8E` | `#A496CF` / `#CABFEF` | AI Engineering                          |

Dark-theme neutrals (background, surfaces, borders, text greys, frame lines and the clay dock) are one family, zinc, whose faint cool cast matches `#0D0D0F`; only the pastel accents carry hue. `--fg-soft` is `#D4D4D8`, `--border-strong` `#3F3F46`.

`*-fg` variants are the only accent colors allowed on text; each meets 4.5:1 against `--bg` and `--surface` in its theme. Fill variants are used only for dots, lines and soft tints (`color-mix` at ≤ 18 %).

## Project screenshots

Every project and client-work screenshot is **5 × 3.5 in (10:7)**, supplied by the owner and exported as `public/projects/<id>.webp` at 1600 × 1120 (WebP, quality 82). They are shown unaltered: never cropped, re-captured or replaced without the owner's file. `tests/data.test.ts` fails if a declared size is not 10:7 or the file's real size differs.

## Typography

- Geist Sans (via the `geist` package, self-hosted by `next/font`) for everything; Geist Mono for section indices, pipeline labels, dates and architecture flows.
- Instrument Serif (via `next/font/google`, downloaded at build time and self-hosted, not preloaded) only for case-study project titles (`type-display-serif`, regular weight, `clamp(1.75rem, 1.4rem + 1.1vw, 2.375rem)`). It has a single weight, so it is never bolded.
- Every section uses the same type scale, defined once as utilities in `src/app/globals.css`. Use these instead of ad-hoc `text-[…]` sizes:

| Utility              | Size / style                                  | Color | Role                                                         |
| -------------------- | --------------------------------------------- | ----- | ------------------------------------------------------------ |
| `type-eyebrow`       | Geist Mono 12 px, +0.025em                    | muted | Section index (“02 / Projects”), 404 code                    |
| `type-section-title` | `clamp(1.5rem, 1.2rem + 1vw, 2rem)`, 600      | fg    | Every section `h2`                                           |
| `type-page-title`    | `clamp(1.75rem, 1.3rem + 1.6vw, 2.5rem)`, 600 | fg    | Page `h1` (projects, project detail, 404)                    |
| `type-lead`          | 15 px / 1.65                                  | muted | Section and page introductions                               |
| `type-prose`         | 15 px / 1.7                                   | (set) | Long-form text on project pages                              |
| `type-card-title`    | 17 px / 1.35, 600                             | fg    | Every card heading, project-page subsection headings         |
| `type-body`          | 14 px / 1.65                                  | (set) | Card descriptions, bullets, lists, contact details           |
| `type-small`         | 13 px / 1.55                                  | (set) | Notes, form labels and messages, legends, footer             |
| `type-label`         | Geist Mono 11 px, +0.02em                     | (set) | Status, group labels, codes, form/contact labels, hero strip |
| `type-mono`          | Geist Mono 12 px                              | (set) | Dates and flow diagrams                                      |
| `type-action`        | 13 px, 500                                    | (set) | Card actions, back links, buttons                            |

“(set)” means the utility carries no color: pair it with one `text-*` class. Never combine a utility that has a color with another color class (the winner is not guaranteed). Form inputs use 16 px so iOS does not zoom on focus. Navigation stays 13 px; the hero name and Tag chips (12 px) keep their own sizes.

- Section headings `clamp(1.5rem, 1.2rem + 1vw, 2rem)`; hero name in Geist Mono at `clamp(1.875rem, 1rem + 2.2vw, 3rem)` (one line from 1280 px, balanced onto two lines below).
- Text measure: paragraphs capped at `60–68ch`.

## Layout

- No global max-width. Each section is a full-width band on the same `--bg` background (no tone alternation; every card and panel sits on `--surface`, so cards read identically in every section) framed by aligned 1 px vertical rails. Between sections, a 20–32 px strip uses fine diagonal hatching and square junction markers. Vertical rails are inset `clamp(16px, 5vw, 80px)` from each side; horizontal divider borders continue to both viewport edges, including at the footer. Hatching fills the side gutters and the center remains clear, with square markers at every rail intersection. A section that follows one ending in an action strip (the hero overview, “View all projects”) omits its own divider band and markers and starts flush against that strip, so two bands never stack.
- Inner content uses `.container-fluid`: fluid content gutters `clamp(32px, 7.5vw, 120px)`, content capped at 1600 px only so 4K screens keep a readable grid.
- Section header: a rectangular panel with a soft neutral tint and 1 px border; mono index (`02`) + title + lead on the left, optional meta on the right (stacks on mobile).
- Grids: projects 1 → 2 (`md`) → 4 (`2xl`) columns; skills 1 → 3 (`lg`); certifications 1 → 3 (`md`); experience date column appears at `md`.
- Touch targets ≥ 40 px (44 px for primary actions and mobile menu items).

Section framing is implemented in `SectionFrame` and plain CSS (`border`, pseudo-elements and `repeating-linear-gradient`), with light/dark tokens for lines, hatching, tint and markers. Decorative guides are hidden from assistive technology and do not intercept input; forced-colors mode removes the hatching and markers. Contact information and its form use matching shaded panels.

## Experience timeline

A vertical, scroll-down timeline (newest first). From `md`: three columns — dates (11 rem, `position: sticky` below the dock so they stay beside a long card), the rail (3.5 rem), and one `card` per role. Below `md`: the rail runs down the left (2.75 rem) and the dates sit above each card.

- **Rail:** a 2 px `--border-strong` segment from each node to the next. Nodes (11 px) align with the card title from `md` and with the date line on phones (`--exp-node-c`). The current role's node is sage with a soft halo.
- **Scroll progress:** with CSS scroll-driven animations (`animation-timeline: view()`), each segment fills and each node lights up as it passes the middle of the viewport. No JavaScript. Skipped with `prefers-reduced-motion` and in browsers without support, which show the static rail.
- **Concurrency:** when a role starts before the next (older) one ended, a sage bracket beside the rail joins the two nodes (Buzzerboy alongside Fujitsu). A handover in the same month is not treated as overlap. The card note explains it in words.
- **Dates:** range in `type-mono`, then the computed inclusive duration (“4 yrs 3 mos”) or “Current role”, then employment type, all in `type-label`.

## Certifications

One `card-shell` panel split into equal cells by hairlines (the hero overview's cell language), each led by the official Credly badge for that credential. Badges are the section's only saturated color; they are shown unaltered and are decorative (`alt=""`) because the certification name sits beside them. Each cell: name (`type-card-title`, two lines reserved in columns so rows align), exam code chip and level (`type-label`), issuer, and “Verify on Credly”. Three columns from `lg`; below that, badge-left rows (80 px badge, 96 px from `sm`). No standalone AWS logo is used (trademark guidelines allow earners to display their badges, not the AWS logo).

## Logo

`src/lib/brand.ts` holds one stroke path on a 32×32 grid (condensed A, light-lean slash, B with a slightly larger lower bowl). Available through `Logo` (current text color) and used by `src/app/icon.svg` (light strokes on `#111827`) and the Open Graph image. Paths, not text, so it never depends on installed fonts; readable at 16 px.

## Hero

Full first viewport (`min-height: 100vh; min-height: 100svh`), portrait and introduction vertically centered below the navigation, with the overview strip anchored at the bottom, and allowed to grow on small screens. Background: plain `--bg`, without a grid or dot pattern. The continuous section rails also frame the hero; the overview strip spans the full framed container beneath both hero columns, with edge-to-edge horizontal rules, hatched side gutters and square intersections.

The overview has four equal-width, equal-height cells: Building (full-stack applications), Experience (7+ years), Certified (AWS 3×), and Reach out (Start a conversation). All four values use the same sans-serif size and weight (14 px on mobile, 16 px from `sm`). The AWS value links to Certifications and the last cell links to Contact; both use the same arrow (`TileArrow`: right arrow in a solid `fg` circle that slides right on hover). Both links are clickable across their tiles. All four fill the framed width in one row on desktop and a two-by-two grid on smaller screens. The owner-provided portrait is served as an optimized local WebP, centered above the centered introduction below `lg` (photo, name, roles, description, actions and links share one axis; the link-row divider fits its links) and in the left column from `lg`, where the introduction is left-aligned, with the introduction on the right. Desktop uses a two-column grid (portrait auto width, text `minmax(0, 1fr)`) with a single 48–64 px gap, so photo and text read as one centered group. The portrait keeps a square crop (224 px mobile, 288 px `sm`, 304 px `lg`, 352 px `xl`, 384 px `2xl`), grayscale and a faint halftone texture; the image asset is unchanged. A hairline divider separates the actions from the GitHub, LinkedIn and email links. A muted “Based in the Philippines” line with a map-pin icon (`type-small`, from `site.basedIn`) sits above the name, aligned with the top of the portrait on desktop. Text actions and GitHub, LinkedIn and email links sit below the introduction. At desktop widths (1024 px and above), email copies the address and announces success; on smaller screens and without JavaScript it opens the native mail client. Clipboard failures expose the address for manual copying. The hero ends with the four-cell overview; the delivery pipeline strip has been removed.

## Case studies (home Projects)

Modeled on a “curated work” layout, client work first, then open source.

- **Frame (desktop):** the case layout spans the section rails (`.section-guides`), with a `--frame-line` border top and bottom; the “View all projects” strip closes it, so its top line is the layout's bottom border. A vertical `--frame-line` divider splits the columns: 65% cards, 35% details and ruler (`13fr 7fr`).
- **Card column (desktop):** filled with the section-divider hatch; cards are inset by the rail-to-content distance (`--gutter − --frame-inset`), so they line up with the section header, and each has a thin `--frame-line` bezel 6 px outside its edge. The details panel uses the same inset at the top and right, and 40–72 px from the divider on the left.
- **Progress ruler (desktop):** between the divider and the pinned title (10 px from the title), one 2 px tick per project, 12 px apart. The active tick is full length (20 px) in the project's discipline tint with a soft glow; the others are `--muted` and shrink and fade with distance (58% / 80%, 34% / 50%, 20% / 30%). The ruler slides so the active tick stays level with the active title (instant with reduced motion). Decorative only (`aria-hidden`).
- **Left column (desktop): preview cards.** Each project is a 4:3 claymorphic card: the dock's clay at card size (`--clay-top` → `--clay-bottom` with `--clay-card-shadow`: lit top lip, inner glow, shaded underside, deep drop shadow, no border), shaded diagonally from dark at the top left (5 % discipline color into `--bg`) to lighter at the bottom right (22 % into `--clay-top`), never saturated; auto height on phones. Each card's background is a four-stop 145° gradient. A card with a screenshot has its own, picked to complement the image: IronFort navy → blue → periwinkle (`#0B1530` → `#1E3A8A` → `#3C64D3` → `#A5B8F0`, from its navy page and brand blue), Website Portfolio deep green → sage (`#142019` → `#2F4A37` → `#6F9A78` → `#B4D3B8`, the site's sage beside a black-and-white screenshot). Cards without a screenshot use the neutral grey (`#1F2937` → `#4B5563` → `#9CA3AF` → `#D1D5DB`). The dark stops sit under the white tagline. With a mouse, a 30 % black overlay (`::before`, under the tagline and screenshot, so the image is never darkened) dims each card's background until it's hovered, then fades out over 400 ms so the card brightens (no overlay on touch screens, in forced colors, or animation with reduced motion). **Rule:** its screenshot (`.case-shot`) has a 2 px frame in the gradient's second-lightest stop on the top and sides; the bottom edge keeps its 2 px but stays transparent until the card is hovered, then shows in the same color (`stageFrame()`, `--stage-frame`). Following the owner's reference card: about 85 % of the card's width, top corners 6 px, a three-layer shadow (1 px ring, 4/16 px and 18/50 px drops), resting 20 px low so its bottom edge sits on the card's edge, tilted 1° below `lg` (with 6 px extra room so the bottom frame stays visible; full width on phones). On desktop hover it animates (700 ms, `cubic-bezier(0.22, 1, 0.36, 1)`; 450 ms out) to `perspective(1200px) rotateX(6deg) translateY(-0.5rem) rotate(1deg) scale(1.045)` from its bottom edge; no motion with reduced motion. The diagonal hatch behind the cards (`.case-list`) is unchanged. It opens with the project's one-line tagline (medium weight, 16–20 px, `--fg`) and an arrow (up-right for external sites, right for case-study pages), then the screenshot rises from the bottom edge as a top-rounded window with 8% side margins, cropped at the bottom when taller than the card. Projects without a screenshot show their real architecture flow in the same window until a picture is added. Cards are mouse-only links (`aria-hidden`, `tabindex=-1`) that lift the preview 6 px on hover; the name and every link live in the details. **100 px (6.25rem) between projects.**
- **Right column (desktop): one pinned details panel** that starts 40 px below the top of the first project's image (`--case-drop`) and, once scrolled, stays centered on screen; after the last project it stops 40 px below the top of that image and scrolls away with it. The panel sticks inside a track sized from the first image to the last, and is as tall as the active project's details (inactive ones float centered on the same point while fading), so it centers exactly and adds no empty space under the last card (sticky `top: max(--nav-offset + 16px, (100svh - panel height) / 2)`, with the panel height measured by a `ResizeObserver`; panels are centered within a cell sized to the tallest, so every project's details are centered). It shows one project at a time: name in Instrument Serif with a small uppercase kind, technology tags, summary, role (client work), short highlights with sage plus markers, primary action and repository/package links. A project takes over once 25% of its image is in the upper half of the viewport (beside the panel) and hands back when it drops below that, in both scroll directions; panels cross-fade (instant with reduced motion).
- **Project cursor (mouse only):** over a card the native cursor is replaced by a 92 px light disc (neutral `#fafafa`→`#d4d4d8`, not a pastel accent) with “VIEW · EXPLORE · DISCOVER ·” in 13 px semibold caps rotating once every 12 s around a 44 px white circle with an eye icon, inside a 102 px dotted ring. It follows the pointer with a soft lag, scales in from 60% over 300 ms, and fades out when the pointer leaves the card. Limited to `(hover: hover) and (pointer: fine)`; with reduced motion it does not spin or lag; under forced colors it is removed and the native cursor stays. Decorative (`aria-hidden`).
- **Accessibility:** all panels stay in the document so assistive technology can read every project; inactive panels are only visually hidden, and focusing a link in one activates it. Without JavaScript the panels stack.
- **Phones and tablets (below `lg`):** no panel; each image is followed by its own details, 100 px between projects.
- Adding `screenshot` to a project in `src/data/projects.ts` replaces its flow window automatically.

The All projects page keeps the compact card grid as an index.

Commercial work without a public repository is shown as a wide `ClientWorkCard`. With a genuine screenshot, the image takes the left 7/12 from `lg` (vertically centered when the details run taller) and every detail stacks on the right; below `lg` the image sits full width on top. ## Project pages

Both pages are built from the same framed bands as the home page (`Section` with rails, hatched dividers and junction markers), so they read as part of one site.

- **All projects (`/projects/`):** a first band (`first`: no divider above it, room for the dock, no entrance fade so the `h1` paints immediately) with the back link, a header panel (“All projects”, lead, project count) and the card grid, closed by an `ActionStrip` linking to GitHub.

## Motion

Each section moves in a way that suits its content, CSS only (no JavaScript beyond the shared `IntersectionObserver` in `RevealObserver`). Entrances are keyframe animations with `fill-mode: backwards`, so they style an element only while it enters and then hand control back to hover transitions. Content is hidden only under `html.js` with motion allowed: without JavaScript or with `prefers-reduced-motion: reduce`, everything is simply visible.

| Where                                         | Effect                                                                                                                                                                                                                             |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hero (page load, the one orchestrated moment) | Portrait opens like an aperture (clip-path + slight scale, no opacity fade, so LCP is not delayed); location, name, roles, tagline, actions and links rise in sequence (90 ms steps); the “At a glance” cells follow left to right |
| Section header panels                         | Rise (`data-reveal`)                                                                                                                                                                                                               |
| Projects / all projects                       | Cards cascade by grid position (`data-reveal-group`, `--i` via `stagger()`)                                                                                                                                                        |
| Experience                                    | Each role slides in from the right (`data-reveal="slide"`), alongside the scroll-driven rail fill and node lighting                                                                                                                |
| Skills                                        | Discipline cards cascade; tags ripple in quickly (`data-reveal-group="ripple"`, 22 ms steps)                                                                                                                                       |
| Certifications                                | Badge cells pop in sequence (`data-reveal-group="pop"`)                                                                                                                                                                            |
| Contact, project detail bands                 | Panels and cards rise in sequence                                                                                                                                                                                                  |
| Project pages’ first band                     | The “at a glance” cells cascade on load like the hero                                                                                                                                                                              |

Cascades cap their delay (8 steps for cards, 24 for tags) so long lists never feel slow. Durations 450–800 ms with `cubic-bezier(0.2, 0.8, 0.2, 1)`. Motion for React remains limited to the lazily loaded mobile menu panel; hover states, the theme icon and these entrances are CSS.

## Prohibited

Gradient or colored display text, neon, saturated gradients, stock photos, glowing cards, decorative patterns beyond the portrait texture and section hatching, percentage skill bars, fake screenshots or badges, duplicate navigation.

## Connect (home section and `/connect/`)

Modeled on the owner's reference contact page. Nav label “Connect” (`#connect`); title “Tell me what you're building”. A shared `ConnectPanel` has three columns from `lg` (two from `md`, stacked on phones):

- **Who:** the portrait as a tilted instant photo (`connect-polaroid`, grayscale), name in Instrument Serif, a sage dot with live local time (Asia/Manila; empty in the static HTML, filled after hydration) and the location.
- **What brings you here?** Toggle buttons (`aria-pressed`): Project, Role, Just a hey. The choice shows a short serif-italic note (announced politely) and, on `/connect/`, fills the form's subject until the visitor edits it.
- **Or reach me directly:** an email card with a Copy button (status announced), then LinkedIn, GitHub and résumé icon buttons (40 px).

The home section closes with a “Send a message” strip to `/connect/`, which adds Book a call / Send a message tabs below the panel. The form sends only through the contact API: a sending state on the button, a success panel (sage check, “Message sent. Thank you, {name}.”, reply address, “Send another message”) and an error alert that keeps the message, names the reason, offers the email address and turns the button into “Try again”. The reference's call booking is omitted: there is no booking service to link to.
