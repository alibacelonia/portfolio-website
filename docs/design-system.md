# Design system

Premium, minimalist, full-width, with restrained operating-system details (a sticky glass navigation dock; reusable frosted surfaces and controls throughout). The typographic **A/B** mark is used for site identity assets. Hierarchy comes from size, weight, spacing and contrast — never from colored or gradient text, except the aurora word in section titles.

## Tokens

Defined as CSS variables in `src/app/globals.css` and exposed to Tailwind through `@theme inline`.

Light and dark themes. **Dark is the default**: before first paint the visitor's saved choice applies, otherwise dark, whatever the device's color scheme; the static HTML and the browser `theme-color` are dark. A sun/moon toggle sits at the end of the dock (desktop) and beside Close in the mobile menu, and remembers the choice. Both themes use the zinc neutral family; case cards use translucent palette tints and theme foreground text in both, the title glow is dark-only, and the aurora word uses darker stops in light mode (each ≥ 3.9:1). Cal.com and Turnstile follow the current theme.

Dark-theme neutrals (background, surfaces, borders, text greys, frame lines and the glass dock) are one family, zinc, whose faint cool cast matches `#0D0D0F`; only the pastel accents carry hue. `--fg-soft` is `#D4D4D8`, `--border-strong` `#3F3F46`.

`*-fg` variants are the only accent colors allowed on text; each meets 4.5:1 against `--bg` and `--surface` in its theme. Fill variants are used only for dots, lines and soft tints (`color-mix` at ≤ 18 %).

## Project screenshots

Every project and client-work screenshot is **5 × 3.5 in (10:7)**, supplied by the owner and exported as `public/projects/<id>.webp` at 1600 × 1120 (WebP, quality 82). They are shown unaltered: never cropped, re-captured or replaced without the owner's file. `tests/data.test.ts` fails if a declared size is not 10:7 or the file's real size differs.

## Section titles

Sections have no top padding or margin: the title block starts right under the section's divider band (first bands keep room for the dock). Every section title (all but the hero) sits in a **title band** (`.section-title-band`), ruled like the reference's “Curated work”: it spans rail to rail, has equal space above and below the title (`clamp(2.5rem, 5vw, 4.5rem)`), the section divider as its top edge and a line below with junction squares at the rails; first bands of a page (`/projects/`, `/connect/`) draw a top line too, and content that draws its own rail-to-rail rule (the case-study layout, `flush`) shares the band's line. Every section opens with the same centered, unboxed heading, after the owner's reference: a plain `div` title block (`section > div.container-fluid > div.title-glow > p + h2`, no `<header>`) with a soft white glow on both lines, holding an overline with the section name (`type-overline`, “CASE STUDIES”) and a display title (`type-display`, an `h2`, or the page's `h1`) whose last word is set in Instrument Serif italic as **aurora text** (`AuroraText`, after Magic UI): a 135° gradient of pink `#FF4FA3`, purple `#B36BFF`, blue `#4F9DFF` and sky `#38BDF8` clipped to the letters, drifting through its colors over 8 s on a still word (no sway) (static with reduced motion, solid in forced colors; brighter than Magic UI's defaults so each stop stays ≥ 5.9:1 on the background): “Curated _work_”. Sections are not numbered. There is no description under the title; a legend or count (`aside`) sits below it. The hero has no overline (its title is the name), and only the project-page header keeps the boxed layout with its category, summary and links.

## Case-study details panel

Same format as the reference's “Curated work” panels: the project name in Instrument Serif (linking to the case study or site) with its category in 10 px uppercase sans; up to four key technologies as pills (`Tag shape="pill"`: rounded, faint fill, theme foreground text); the client role line for client work; highlights in 14 px muted text, each marked with a 20 px four-point sparkle in the card's accent (`stageFrame()`, the gradient's second-lightest stop) with a soft glow; then the main link with a round arrow chip (→ internal, ↗ external) and the secondary links (GitHub, PyPI). The ruler's active tick uses the same accent. No description paragraph (see below).

## Certification badges

With a mouse, each badge leans toward the pointer in 3D (`TiltBadge`: up to 14°, `perspective: 600px`, scale 1.06), following quickly (120 ms) and settling back flat when the pointer leaves (600 ms, `cubic-bezier(0.22, 1, 0.36, 1)`). A soft-light sheen follows the pointer, masked to the badge's own hexagon by its image. Touch, pen and reduced motion leave the badges still. The pointer only sets CSS variables (no re-renders); about 0.4 KB gzipped.

## Reusable glass surfaces

All raised surfaces share `glass`: translucent theme fill, fine rim, restrained top sheen, soft shadow and 20 px backdrop blur. `card-shell`, `card` and `section-panel` compose this material. Use `glass-control` for buttons, selected navigation indicators, icon controls and the email box; `glass-field` for inputs/textarea with a stronger boundary; `glass-chip` for tags, code chips and nested notes (no extra blur layer per small label); `glass-selectable` adds the shared selected state for tabs and intent buttons. Customize a palette with local `--glass-fill` instead of copying the material rules. Floating docks use a denser 90% fill (`--glass-floating-bg`) so small navigation text stays readable even over an image in the opposite color scheme.

Both themes define the same semantic tokens, including text, accents, field boundaries, error colors and media shadows. Text placeholders use the full muted token, and selected controls retain readable foreground text. Browser chrome follows the selected site theme. Cal.com and Turnstile recreate their embeds on theme changes (Turnstile also clears the previous token).

Without backdrop-filter, every material falls back to a solid theme surface. `prefers-reduced-transparency: reduce` disables translucency and blur, while forced colors uses Canvas/CanvasText and Highlight for selected controls. The dock is always glass, including when old build configuration still says clay or neo. Static screenshots and credential artwork retain the owner's original colors; the favicon follows the browser's color scheme.

## No repeated text

Each fact is said once per section: no section descriptions; case-study panels carry the highlights, not the summary; labels that a group heading or a date already convey (“Client work”, “Current role”, the certification issuer) are omitted.

## Typography

- **Two families only:** Geist Sans (via the `geist` package, self-hosted by `next/font`) for all text, labels, dates and data (with tabular figures), and Instrument Serif for display (section titles, the hero name, project names). No monospace face.
- **Sizes in `rem` only** (no `px` font sizes), so text follows the browser's font-size setting as well as zoom; fluid sizes are `clamp()` with `rem` bounds. Body text is `0.9375rem`.
- Instrument Serif (via `next/font/google`, downloaded at build time and self-hosted, not preloaded) for display: section titles, the hero name, and **every project name**, so a project reads the same wherever it appears: case-study panels (`type-display-serif`, `clamp(1.75rem, 1.4rem + 1.1vw, 2.375rem)`), the `/projects/` and client-work cards (`type-project-title`, `clamp(1.5rem, 1.35rem + 0.5vw, 1.75rem)`) and a project page's `h1` (`type-project-page-title`, `clamp(2.25rem, 1.7rem + 2vw, 3.25rem)`). It has a single weight, so it is never bolded.
- Nothing is set below 12 px (`0.75rem`); the case panels' kind label uses `type-overline`.
- Every section uses the same type scale, defined once as utilities in `src/app/globals.css`. Use these instead of ad-hoc `text-[…]` sizes:

- Text measure: paragraphs capped at `60–68ch`.

## Layout

- No global max-width. Each section is a full-width band on the same `--bg` background (no tone alternation; every card and panel sits on `--surface`, so cards read identically in every section) framed by aligned 1 px vertical rails. Between sections, a 20–32 px strip uses fine diagonal hatching and square junction markers. Vertical rails are inset `clamp(16px, 5vw, 80px)` from each side; horizontal divider borders continue to both viewport edges, including at the footer. Hatching fills the side gutters and the center remains clear, with square markers at every rail intersection. A section that follows one ending in an action strip (the hero overview, “View all projects”) omits its own divider band and markers and starts flush against that strip, so two bands never stack.
- Inner content uses `.container-fluid`: fluid content gutters `clamp(32px, 7.5vw, 120px)`, content capped at 1600 px only so 4K screens keep a readable grid.
- Section header: see **Section titles** (centered overline and display title in a title band).
- Grids: projects 1 → 2 (`md`) → 4 (`2xl`) columns; skills 1 → 3 (`lg`); certifications 1 → 3 (`md`); experience date column appears at `md`.
- Touch targets ≥ 40 px (44 px for primary actions and mobile menu items).

Section framing is implemented in `SectionFrame` and plain CSS (`border`, pseudo-elements and `repeating-linear-gradient`), with light/dark tokens for lines, hatching, tint and markers. Decorative guides are hidden from assistive technology and do not intercept input; forced-colors mode removes the hatching and markers. Contact information and its form use matching shaded panels.

## Experience timeline

A vertical, scroll-down timeline (newest first). From `md`: three columns — dates (11 rem, `position: sticky` below the dock so they stay beside a long card), the rail (3.5 rem), and one `card` per role. Below `md`: the rail runs down the left (2.75 rem) and the dates sit above each card; the two most recent roles show their summary points, earlier roles (`data-earlier`) only their title, organization and “Show details”, whose list repeats those points in full.

- **Rail:** a 2 px `--border-strong` segment from each node to the next. Nodes (11 px) align with the card title from `md` and with the date line on phones (`--exp-node-c`). The current role's node is sage with a soft halo.
- **Scroll progress:** with CSS scroll-driven animations (`animation-timeline: view()`), each segment fills and each node lights up as it passes the middle of the viewport. No JavaScript. Skipped with `prefers-reduced-motion` and in browsers without support, which show the static rail.
- **Concurrency:** when a role starts before the next (older) one ended, a sage bracket beside the rail joins the two nodes (Buzzerboy alongside Fujitsu). A handover in the same month is not treated as overlap. The card note explains it in words.
- **Dates:** range in `type-mono`, then the computed inclusive duration (“4 yrs 3 mos”, none for the current role, whose range ends in “Present”), then employment type, all in `type-label`.

## Hero

Full first viewport (`min-height: 100vh; min-height: 100svh`), portrait and introduction vertically centered below the navigation, with the overview strip anchored at the bottom, and allowed to grow on small screens. Background: plain `--bg`, without a grid or dot pattern. The continuous section rails also frame the hero; the overview strip spans the full framed container beneath both hero columns, with edge-to-edge horizontal rules, hatched side gutters and square intersections.

The overview has four equal-width, equal-height cells: Currently (current role and product), Experience (7+ years), Certified (AWS 3×), and Reach out (Start a conversation). All four values use the same sans-serif size and weight (14 px on mobile, 16 px from `sm`). The AWS value links to Certifications and the last cell links to Connect; both use the same arrow (`TileArrow`: right arrow in a solid `fg` circle that slides right on hover). Both links are clickable across their tiles. All four fill the framed width in one row on desktop and a two-by-two grid on smaller screens. The owner-provided portrait is served as an optimized local WebP, centered above the centered introduction below `lg` (photo, name, roles, description, actions and links share one axis; the link-row divider fits its links) and in the left column from `lg`, where the introduction is left-aligned, with the introduction on the right. Desktop uses a two-column grid (portrait auto width, text `minmax(0, 1fr)`) with a single 48–64 px gap, so photo and text read as one centered group. The portrait keeps a square crop (224 px mobile, 288 px `sm`, 304 px `lg`, 352 px `xl`, 384 px `2xl`), in its original color with a faint halftone texture; the image asset is unchanged. On page load it **develops like an instant photo**: it opens in black and white with the aperture, then its color comes in once over about two seconds (`photo-develop`, 300 ms delay) and stays. Reduced motion and no-JavaScript visitors see the color photo from the start. Touch and pen leave it monochrome, reduced motion drops the fade, and forced colors hide the color copy. A hairline divider separates the actions from the GitHub, LinkedIn and email links. A muted “Based in the Philippines” line with a map-pin icon (`type-small`, from `site.basedIn`) sits above the name, aligned with the top of the portrait on desktop. The actions sit below the introduction: “View My Work” as the solid main button (`buttonStyles.solid`) beside the quieter “Download CV” text link (they stack, centered, at 320 px), then the GitHub, LinkedIn and email links. At desktop widths (1024 px and above), email copies the address and announces success; on smaller screens and without JavaScript it opens the native mail client. Clipboard failures expose the address for manual copying. The hero ends with the four-cell overview; the delivery pipeline strip has been removed.

## Case studies (home Projects)

Modeled on a “curated work” layout, client work first, then open source.

- **Frame (desktop):** the case layout spans the section rails (`.section-guides`), with a `--frame-line` border top and bottom; the “View all projects” strip closes it, so its top line is the layout's bottom border. A vertical `--frame-line` divider splits the columns: 65% cards, 35% details and ruler (`13fr 7fr`).
- **Card column (desktop):** filled with the section-divider hatch; cards are inset by the rail-to-content distance (`--gutter − --frame-inset`), so they line up with the section header, and each has a thin `--frame-line` bezel 6 px outside its edge. The details panel uses the same inset at the top and right, and 40–72 px from the divider on the left.
- **Progress ruler (desktop):** between the divider and the pinned title (10 px from the title), one 2 px tick per project, 12 px apart. The active tick is full length (20 px) in the project's discipline tint with a soft glow; the others are `--muted` and shrink and fade with distance (58% / 80%, 34% / 50%, 20% / 30%). The ruler slides so the active tick stays level with the active title (instant with reduced motion). Decorative only (`aria-hidden`).
- **Left column (desktop): preview cards.** Each project is a 4:3 frosted glass card (auto height on phones). `stageGlassBackground()` mixes every stop of its original palette at 12% into `--glass-bg`, so the card follows both themes while keeping its identity. Cards with screenshots use their own palette; cards without one use `NEUTRAL_STAGE`. Taglines and arrows use `--fg` / `--fg-soft`. A subtle theme-aware veil sits below the content and fades on mouse hover; touch has no veil. The screenshot stays unaltered and keeps its 2 px frame in the original palette’s second-lightest stop (`stageFrame()`), transparent at the bottom until hover. The existing 20 px rest offset, 1° mobile tilt and desktop perspective hover remain. Media shadows follow the theme. Cards are mouse-only links (`aria-hidden`, `tabindex=-1`); accessible names and links remain in the details. The flow-window fallback, its step chips, and the custom glass cursor share the reusable material. Projects remain 100 px apart in the hatched column.
- **Cards without a screenshot** show the project's real architecture flow (`infrastructure.diagram`) in a glass window that fills the card under the tagline: from `sm` the steps alternate left and right of a vertical spine in equal rows, each marked by a node in the card's frame color (`--stage-frame`), so no card shows an empty box. On phones the window is as tall as a compact wrapped row of chips joined by arrows.
- **Right column (desktop): one pinned details panel** that starts 40 px below the top of the first project's image (`--case-drop`) and, once scrolled, stays centered on screen; after the last project it stops 40 px below the top of that image and scrolls away with it. The panel sticks inside a track sized from the first image to the last, and is as tall as the active project's details (inactive ones float centered on the same point while fading), so it centers exactly and adds no empty space under the last card (sticky `top: max(--nav-offset + 16px, (100svh - panel height) / 2)`, with the panel height measured by a `ResizeObserver`; panels are centered within a cell sized to the tallest, so every project's details are centered). It shows one project at a time: name in Instrument Serif with a small uppercase kind, technology tags, summary, role (client work), short highlights with sage plus markers, primary action and repository/package links. A project takes over once 25% of its image is in the upper half of the viewport (beside the panel) and hands back when it drops below that, in both scroll directions; panels cross-fade (instant with reduced motion).
- **Project cursor (mouse only):** over a card the native cursor is replaced by a 92 px light disc (neutral `#fafafa`→`#d4d4d8`, not a pastel accent) with “VIEW · EXPLORE · DISCOVER ·” in 13 px semibold caps rotating once every 12 s around a 44 px white circle with an eye icon, inside a 102 px dotted ring. It follows the pointer with a soft lag, scales in from 60% over 300 ms, and fades out when the pointer leaves the card. Limited to `(hover: hover) and (pointer: fine)`; with reduced motion it does not spin or lag; under forced colors it is removed and the native cursor stays. Decorative (`aria-hidden`).
- **Accessibility:** all panels stay in the document so assistive technology can read every project; inactive panels are only visually hidden, and focusing a link in one activates it. Without JavaScript the panels stack.
- **Phones and tablets (below `lg`):** no panel; each image is followed by its own details, 100 px between projects (56 px below `sm`, so the section stays a few screens long). Each phone/tablet details block keeps the first two highlights; all of them stay in the desktop panel and on the project pages. The project name link has a 40 px+ hit area (a pseudo-element, no layout change).
- Adding `screenshot` to a project in `src/data/projects.ts` replaces its flow window automatically.

The All projects page keeps the compact card grid as an index, with discipline filters and a result count above it.

## Motion

Each section moves in a way that suits its content, CSS only (no JavaScript beyond the shared `IntersectionObserver` in `RevealObserver`). Entrances are keyframe animations with `fill-mode: backwards`, so they style an element only while it enters and then hand control back to hover transitions. Content is hidden only under `html.js` with motion allowed: without JavaScript or with `prefers-reduced-motion: reduce`, everything is simply visible.

| Skills                                        | Discipline cards cascade; tags ripple in quickly (`data-reveal-group="ripple"`, 22 ms steps)                                                                                                                                                                                    |
| Certifications                                | Badge cells pop in sequence (`data-reveal-group="pop"`)                                                                                                                                                                                                                         |
| Contact, project detail bands                 | Panels and cards rise in sequence                                                                                                                                                                                                                                               |
| Project pages’ first band                     | The “at a glance” cells cascade on load like the hero                                                                                                                                                                                                                           |

Cascades cap their delay (8 steps for cards, 24 for tags) so long lists never feel slow. Durations 450–800 ms with `cubic-bezier(0.2, 0.8, 0.2, 1)`. Motion for React remains limited to the lazily loaded mobile menu panel; hover states, the theme icon and these entrances are CSS.

## Prohibited

Gradient or colored display text (the one exception is the aurora word in section titles, an owner request), neon, saturated gradients, stock photos, glowing cards, decorative patterns beyond the portrait texture and section hatching, percentage skill bars, fake screenshots or badges, duplicate navigation.

## Connect (home section and `/connect/`)

Modeled on the owner's reference contact page. Nav label “Connect” (`#connect`); title “Tell me what you're building”. A shared `ConnectPanel` has three columns from `lg` (two from `md`, stacked on phones):

- **Who:** the portrait as a tilted instant photo (`connect-polaroid`, in color; it develops from black and white once as its panel reveals), name in Instrument Serif, a sage dot with live local time (Asia/Manila; empty in the static HTML, filled after hydration) and the location.
- **What brings you here?** Toggle buttons (`aria-pressed`): Project, Role, Just a hey. The choice shows a short serif-italic note (announced politely) and, on `/connect/`, fills the form's subject until the visitor edits it.
- **Or reach me directly:** an email card with a Copy button (status announced), then labeled LinkedIn, GitHub and CV buttons (icon plus word, 40 px tall, wrapping on narrow columns; screen readers hear “Download CV (PDF)”).

The home section closes with the page's main call to action: an `ActionStrip` with `prominent`, a solid “Send a message” button to `/connect/`, which adds Book a call / Send a message tabs below the panel. The form sends only through the contact API: a sending state on the button, a success panel (sage check, “Message sent. Thank you, {name}.”, reply address, “Send another message”) and an error alert that keeps the message, names the reason, offers the email address and turns the button into “Try again”. **Book a call** embeds the Cal.com calendar (see `docs/deployment.md`). When a booking goes through, Cal.com's frame posts `bookingSuccessfulV2` (or the reschedule / legacy variants); the site then replaces the calendar with its own confirmation in the same style as the form's success panel: sage check, “Your call is booked” (“Request sent” when the event needs confirmation, “Your call is rescheduled” for reschedules), the event title and time in the visitor's timezone, what email to expect, and “Book another time”, which loads a fresh calendar. The panel takes focus and is announced as a status. This avoids Cal.com's own success page, which turned the frame white.

## Personality and lightweight interactions

The hero keeps its plain background and square portrait. `offset-frame` adds two static, theme-aware accent layers behind the image; it uses pseudo-elements and no animated blur or extra image. A short personal introduction (`site.intro`) sits below the roles, within the existing one-time entrance sequence. The portrait's dimensions, preload and image asset remain unchanged.

Skills use `TechnologyIcon`: selected monochrome Simple Icons paths, rendered inline on the server, with small Lucide category symbols for the remaining technologies. All inherit the current text color. The reusable `SkillTag` opens a native `details` disclosure only when `findSkillProjects()` finds the tool in an existing documented stack or published client-work technology list. It shows up to two references. Matching uses whole terms and explicit API aliases, never planned infrastructure or invented experience. Working-knowledge markers stay intact. One disclosure per discipline opens at a time; an open item occupies its own full row to avoid clipping a tooltip on small screens. These interactions and their native links work without JavaScript. Below `lg`, each discipline shows its first group and folds the rest behind “Show N more” (`SkillGroups`, `aria-expanded`), which keeps the section about half as long on phones; desktop and visitors without JavaScript always see every group. Artwork attribution is in `docs/third-party-notices.md`.

Only `/projects/` renders the small `ProjectFilters` client component. Its server-rendered children retain all project content and links. Counts include published client work; empty categories are omitted until there is content. The current data offers All, DevOps & Cloud and AI Engineering; Full-Stack appears automatically when an entry has that discipline. Pressed buttons, result announcements and CSS filtering work with keyboard and touch. Filtering hides empty group headings, and restored All shows every card. Without JavaScript, filter controls are hidden and the whole index remains visible. Filter entrances use opacity/transform and are disabled with reduced motion. All styles compose the shared glass utilities and theme tokens; no runtime dependency is added.
